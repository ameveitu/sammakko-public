TEACHER VIEW BOUNDARY

The network should publish a manifest that the host teacher view can consume:

  kcId -> lessonPagePath, scaffold/content status, lesson revision,
          Lite alignment status, game-link resolver status

The teacher opens the HTML page for presentation and uses a separately labelled copy action for the desired game's KC link. The lesson-page URL and game URL are different deliverables. Learner profile/history, teacher session state and a specific random item are not part of a generic shared KC link.

Only turn on an ordinary classroom copy/open action when the configured route, exact KC availability and endpoint have been verified, and the deployment is reachable by the intended pupil audience. Distinguish local_preview, classroom_network and public deployment scopes. Source-known but endpoint-unverified routes can be exposed as clearly labelled developer tests. A localhost, loopback or file: link is a local preview, not a shareable classroom link. If unavailable, show the reason and retain useful actions to copy the KC ID or a correctly labelled lesson page link. Missing deployment does not block completion of the local Phase-1 foundation.

MINIMUM INTEGRATION CHECKS

- Copy/paste into a fresh tab opens the exact expected KC on the stated build.
- Reload retains the intended KC where route support is claimed.
- Unknown and unimplemented IDs cannot silently become another exercise.
- The selected game's own prerequisite/preview behavior remains in force.
- Opening/copying/presenting cannot create an answered-attempt, checked state or world reward.
- Direct links remain valid under the configured host path prefix.
- Local preview URLs cannot be labelled ready for pupils on other devices.
- A lesson-network page is never labelled a direct Lite game link.
- The availability manifest, route version and endpoint verification evidence are updated together.
